## 一、OLED 显示系统

### 1.1 显存缓冲 (Display Buffer)

```
OLED_DisplayBuf[8][128]       ← 内存中的虚拟屏幕
          ↓
物理屏幕：128×64 像素 = 8192 个像素点
          ↓
组织方式：8 页 × 128 列
  每页 = 8 个垂直像素（1 字节，位 0~7 对应上方到下方）
  每个字节的第 k 位 → 屏幕坐标 (列号, 页号×8 + k)
```

**坐标约定：**
```
        0          X轴 →        127
     0  .---------------------------.
        |                           |
  Y轴   |      OLED 128×64          |
   ↓    |                           |
    63  '---------------------------'
```

**为什么要缓冲？**

| 直接写 OLED | 缓冲后写 |
|:---:|:---:|
| 每次画点都走 I2C 通信 | 先在内存里画好（微秒级） |
| 画一帧要几百 ms | 画完一次性推（~10ms） |
| 画面撕裂、闪烁 | 人眼看不出刷新 |

**流程：** `画内容到 Buf → OLED_Update() 推送到硬件 → 显示`

### 1.2 反色高亮原理

```c
// OLED_ReverseArea: 指定区域黑白反转
OLED_DisplayBuf[j / 8][i] ^= 0x01 << (j % 8);
//                          ^^^
//                          XOR 操作
```

| 原值 | XOR 1 | 结果 |
|:---:|:---:|:---:|
| 0 (灭) | 1 | 1 (亮) |
| 1 (亮) | 1 | 0 (灭) |

- **XOR 一次** = 反色（黑底白字 → 白底黑字）
- **XOR 两次** = 还原

不需要重新绘制文字，性能极高。

### 1.3 中文显示流程

```
源文件字符串 "菜单" (UTF-8: E8 8F 9C | E5 8D 95)
        ↓
OLED_ShowString() 逐字节解析：
  - 0x00~0x7F → ASCII 单字节
  - 0xE0~0xEF → UTF-8 三字节（中文）
        ↓
解析出 "菜" 的 3 字节 → SingleChar = {E8, 8F, 9C, \0}
        ↓
遍历字库 OLED_CF16x16[]：
  strcmp(Index, SingleChar) == 0  →  找到！
        ↓
取出 Data[32]（16×16 点阵 = 32 字节）
        ↓
OLED_ShowImage() 画到 DisplayBuf
```

**编码必须一致：** 源文件字符串的编码必须和字库 `Index` 的编码完全一致。这就是之前 UTF-8 vs GB2312 出问题的根因。

**ChineseCell_t 结构：**
```c
typedef struct {
    char Index[5];      // 汉字编码（UTF-8 最多 4 字节 + \0）
    uint8_t Data[32];   // 16×16 点阵数据
} ChineseCell_t;
```

## 二、RTC 实时时钟

### 2.1 时钟源选择：LSE vs LSI

| | LSE（外部 32.768kHz 晶振） | LSI（内部 RC 振荡器） |
|:---|:---|:---|
| 精度 | ±20ppm ≈ 年误差 < 1 分钟 | ±1% ≈ 一天能差 15 分钟 |
| 功耗 | 极低 | 低 |
| 掉电保持 | 备用电池 VBAT 供电，继续走 | 主电一断就停 |
| 起振 | 偶尔不起振 | 稳定 |

> **手表必须用 LSE**，不然时间不准。

### 2.2 预分频器原理

```
LSE 晶振频率 = 32768 Hz
预分频器     = 32768 - 1
分频后       = 32768 ÷ 32768 = 1 Hz

RTC_CNT 计数器每秒 +1
→ CNT 的值就是 Unix 时间戳（从 1970-01-01 00:00:00 UTC 算起的秒数）
```

### 2.3 时区处理

```c
// 写入 RTC：北京时间(UTC+8) → UTC
time_cnt = mktime(&time_date) - 8 * 60 * 60;

// 读取 RTC：UTC → 北京时间
time_cnt = RTC_GetCounter() + 8 * 60 * 60;
```

**设计原则：** RTC 硬件永远存 UTC（标准时间），显示时才转本地时间。全球通用。

### 2.4 备份寄存器标记

```c
// 首次上电：配置 RTC → 写标记
BKP_WriteBackupRegister(BKP_DR1, 0xA5A5);

// 再次上电：读到标记 → 跳过配置（RTC 靠电池一直在走）
if (BKP_ReadBackupRegister(BKP_DR1) != 0xA5A5) { ... }
```

## 三、定时器中断 (TIM2)

### 3.1 为什么是 1ms？

```
系统主频 72MHz
    ÷ PSC(720)   = 100 KHz     每个 tick = 10μs
    ÷ ARR(100)   = 1000 Hz     每 1ms 中断一次
```

**72,000,000 ÷ 720 ÷ 100 = 1000 Hz**

> 1ms 足够精细，既能做按键消抖（20ms = 20 次），又能做 UI 刷新计时。

### 3.2 中断里只做轻量的事

```c
void TIM2_IRQHandler(void) {
    Key_Tick();  // 只打标签，不干重活
}
```

- ✅ 中断里：状态标记、计数累加
- ❌ 中断里不干：画屏、读 RTC、printf（太重，会阻塞其他中断）

## 四、按键扫描与消抖

### 4.1 为什么需要消抖？

按键按下时，电平不会干净地跳变，而是抖动 5~20ms：

```
松开 ──┬─┐   ┌─── 按下
       │ └─┘ └─┐
       │       ├── 抖动期（~10ms）
       └───────┴── 稳定按下
```

不消抖的话，一次按键会被识别为多次。

### 4.2 软件消抖状态机

```
每 1ms 调一次 Key_Tick()：
  Count 累加直到 ≥ 20（即 20ms 采样一次）

  20ms 时：
    保存 PreState ← CurrentState
    读取 CurrentState ← 当前 GPIO 电平
    如果 PreState≠0 且 CurrentState==0（按键松开瞬间）
      → Key_Num = PreState（上报按键值）
```

**为什么松开时才触发？**
- 手感自然：按下选中，松手确认
- 防重复：按住不放只触发一次

### 4.3 按键编号

| 按键 | GPIO | 返回值 | 功能 |
|:---|:---|:---:|:---|
| Key1 | PB1 | 1 | 上一个 / 左移 |
| Key2 | PA6 | 2 | 下一个 / 右移 |
| Key3 | PA3 | 3 | 确认 |

## 五、主程序架构

### 5.1 阻塞式 UI 循环

```c
main() {
    初始化所有外设;
    while (1) {
        clkflag = First_Page_Clock();  // 阻塞！直到按确认键才返回
        if (clkflag == 1) { /* 菜单 */ }
        if (clkflag == 2) { /* 设置 */ }
    }
}

First_Page_Clock() {
    while (1) {
        读按键 → 切换选项 → 重绘全屏 → OLED_Update()
        if 确认键 → return;
    }
}
```

**适合单片机：** 单任务最简单。后面 1-3 滑动菜单时会升级架构。

### 5.2 全屏重绘为什么不会闪？

OLED_Update() 是 I2C 突发写（1.3Mbps 左右），一帧约 10ms。人眼暂留效应是 16ms，所以完全看不出闪烁。
