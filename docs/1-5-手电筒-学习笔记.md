# 1-5 手电筒 — 学习笔记

## 学习目标

本节重点是复习 GPIO 输出控制，以及理解“板载 LED”和“真正手电筒”在硬件上的区别。

对应代码：

- `APP/src/app_flashlight.c`
- `HARDWARE/src/LED.c`
- `HARDWARE/inc/board_config.h`

## 单片机知识点

### 1. GPIO 输出

STM32 控制 LED 的本质是控制某个 GPIO 引脚输出高低电平。

项目中板载 LED 使用 PC13：

```c
#define LED_PORT GPIOC
#define LED_PIN  GPIO_Pin_13
```

初始化时需要：

1. 开启 GPIOC 时钟。
2. 配置 PC13 为推挽输出。
3. 设置默认输出状态。

### 2. 低电平点亮

很多 STM32 最小系统板的 PC13 LED 是低电平有效：

```text
PC13 = 0 -> LED 亮
PC13 = 1 -> LED 灭
```

所以 `LED_ON()` 和 `LED_OFF()` 不能只凭名字猜输出电平，要看硬件连接。

### 3. 板载 LED 的限制

当前“手电筒”只是控制板载 LED。它能验证 GPIO 输出逻辑，但亮度和照明效果有限。如果要做真正手电筒，通常需要：

- 外接高亮 LED。
- 三极管或 MOSFET 驱动。
- 限流电阻。
- 电源电流能力评估。

## 代码解析

### `LED_Init()`

硬件驱动层负责初始化 GPIO：

- 开启 `LED_RCC`。
- 配置 `LED_PIN`。
- 默认关闭 LED。

### `App_Flashlight_Run()`

应用层只关心交互：

- 返回。
- OFF。
- ON。

确认高亮项后调用：

```c
LED_OFF();
LED_ON();
```

## 注意点

- `LED.c` 属于硬件驱动，`app_flashlight.c` 属于应用页面。
- PC13 低电平有效，代码里的 ON/OFF 要和硬件实际连接对应。
- 当前页面是阻塞式循环，按返回后才回到菜单。
- 如果以后改成外接强光 LED，不应该改 APP 页面，应优先改硬件驱动或新增驱动。
