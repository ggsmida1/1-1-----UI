# 1-11 项目结构重构 — 学习笔记

## 学习目标

本节重点不是新增功能，而是整理项目结构，让代码更容易读、改、定位问题。

对应代码结构：

- `APP/`
- `HARDWARE/`
- `RES/`
- `SYSTEM/`
- `USER/`

## 为什么要重构

功能刚开始少时，把逻辑都放在 `main.c` 或一个大 `menu.c` 中可以跑起来。但功能变多后会出现问题：

- 页面逻辑、硬件驱动、资源数据混在一起。
- 文件名不能准确表达职责。
- 修改一个功能时需要翻很多无关代码。
- Keil 工程文件里路径越来越难维护。

重构的目标不是“看起来高级”，而是让每个目录和文件职责明确。

## 当前目录职责

```text
APP/       应用层：页面、菜单、小游戏、应用入口
HARDWARE/  硬件驱动层：OLED、Key、LED、ADC、MPU6050、软件 I2C
RES/       UI 资源层：字模、图标、图片数组
SYSTEM/    系统基础：Delay、Timer、RTC、USART
USER/      Keil 工程入口：main、工程文件、中断文件
```

## 关键重构点

### 1. 从 `menu.c` 拆出应用模块

原先菜单、首页、设置、应用调度容易混在一起。现在拆成：

```text
app_home.c       首页时钟
app_menu.c       横向菜单和应用调度
app_settings.c   设置入口页
app_set_time.c   日期时间设置
app_launcher.c   应用初始化
app_tick.c       1ms 应用节拍
```

这样每个文件只关注一个主题。

### 2. 应用入口统一命名

应用入口统一成：

```text
App_Stopwatch_Run()
App_Flashlight_Run()
App_MPU6050_Run()
App_Dino_Run()
App_Emoji_Run()
App_Gradienter_Run()
```

看到 `App_xxx_Run()` 就知道它是一个应用页面入口。

### 3. 驱动和资源分离

`OLED.c` 是驱动，负责显示函数。

`ui_resources.c` 是资源，负责字模、图标、图片数组。

它们不应混为一类，所以资源放到 `RES/`。

### 4. 1ms tick 集中调度

`main.c` 中断里只调用：

```c
App_Tick_1ms();
```

具体调度放在 `APP/src/app_tick.c`：

```c
Key3_Tick();
Key_Tick();
App_Stopwatch_Tick();
App_Dino_Tick();
```

这样 `main.c` 不需要知道每个应用的内部节拍函数。

### 5. 引脚集中管理

`board_config.h` 保存引脚和外设映射：

```text
OLED: PB8/PB9
MPU6050: PB10/PB11
Key: PB1/PA6/PA3
LED: PC13
ADC: PA0
```

换板子时优先改这里，而不是到每个驱动文件里找引脚。

## 头文件原则

### 推荐做法

`.h` 只暴露接口必须知道的内容，`.c` 包含实现需要的依赖。

```c
// app_launcher.h
void App_Init(void);

// app_launcher.c
#include "app_launcher.h"
#include "AD.h"
#include "Key.h"
#include "LED.h"
```

这样调用者 include `app_launcher.h` 时，不会被迫知道 AD、Key、LED、MPU6050 的细节。

### 头文件自包含

如果头文件里用到 `uint16_t`、`GPIO_TypeDef` 等类型，就必须自己 include 对应头文件。否则别人单独 include 它时会报错。

## 重构后的收益

- 新增应用时，只需要新增 `APP/inc/app_xxx.h` 和 `APP/src/app_xxx.c`。
- 修改硬件引脚时，优先看 `board_config.h`。
- 修改图片资源时，优先看 `RES/`。
- 修改菜单调度时，优先看 `app_menu.c`。
- 修改周期任务时，优先看 `app_tick.c`。

## 注意点

- 重构后必须同步 Keil 工程文件 `USER/Template.uvprojx`。
- `.uvoptx` 是用户本地选项文件，通常不作为正式工程文件提交。
- `OBJ/`、`USER/Listings/` 是构建输出，不属于源码。
- 不要为了分层继续无限拆文件，当前体量保持 APP/HARDWARE/RES/SYSTEM/USER 已经足够。
