## 一、从零理解单片机

### 1.1 单片机是什么

```
┌─────────────────────────────────┐
│           单片机芯片             │
│  ┌─────┐ ┌──────┐ ┌──────────┐ │
│  │ CPU │ │ 内存  │ │ 外设     │ │
│  │ ARM │ │SRAM  │ │GPIO TIM  │ │
│  │Cortex│ │20KB  │ │I2C SPI  │ │
│  │ -M3 │ │      │ │USART ADC │ │
│  │72MHz│ │      │ │RTC  DMA  │ │
│  └─────┘ └──────┘ └──────────┘ │
│  ┌─────┐ ┌──────────┐          │
│  │Flash│ │  总线矩阵  │          │
│  │64KB │ │(连接一切)│          │
│  └─────┘ └──────────┘          │
└─────────────────────────────────┘
```

**和电脑的区别：** 电脑跑操作系统、多任务、几十 GB 内存；单片机裸机跑、单任务为主、几十 KB 内存。但编程逻辑是一样的——内存、外设、中断，只是规模不同。

### 1.2 你代码的编译到烧录流程

```
menu.c ─┐
OLED.c ─┤
　　　　├→ ARMCC编译器 → Template.axf (二进制) 
main.c ─┘                        ↓
                            ST-Link 烧录器
                                  ↓
                          STM32 Flash 存储器
                                  ↓
                    上电 → CPU 从 Flash 读第一条指令
```

**烧录就是把编译好的二进制写进芯片的 Flash 里，断电不丢。**

## 二、GPIO — 最基础的外设

### 2.1 引脚能干什么

每个 GPIO 引脚本质上是一根可以**读电平（输入）**或**控制电平（输出）**的线。

```
输出模式：CPU → GPIO → 外部器件（如 LED、OLED_SDA）
输入模式：外部器件 → GPIO → CPU（如按键）
```

### 2.2 四种输出模式

| 模式 | 原理 | 特点 | 用在哪 |
|:---|:---|:---|:---|
| **推挽 Push-Pull** | 两个开关，一个接 VCC 一个接 GND，输出必为高或低 | 驱动能力强 | LED、普通 IO |
| **开漏 Open-Drain** | 只有一个开关接 GND，输出低/高阻。要出高电平得靠外部上拉电阻 | 允许多设备共享一根线 | **I2C 总线** |

```
推挽输出：                开漏输出：
   VCC                   VCC
    │                     │
 ┌──┴──┐                ──┼── 上拉电阻（外部）
 │P-MOS│ 开→高          ┌──┴──┐
 └──┬──┘               │N-MOS│ 开→低
    ├─── 输出           └──┬──┘
 ┌──┴──┐                  ├─── 输出
 │N-MOS│ 开→低             │
 └──┬──┘                  ╧
    │                     GND
   GND
```

### 2.3 上下拉电阻

```
上拉 (Pull-Up)：引脚 → 电阻 → VCC
  - 默认高电平，按下接 GND 变低
  - 你的按键：GPIO_Mode_IPU（内部上拉）

下拉 (Pull-Down)：引脚 → 电阻 → GND
  - 默认低电平，按下接 VCC 变高
```

**你的 Key.c 用 `IPU`：** 按键不按时读到 1（高），按下读到 0（低）→ 低电平有效。

### 2.4 回到项目验证

```c
// OLED 用开漏（为什么？I2C 要求！）
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;  // PB8=SCL, PB9=SDA
// I2C 总线允许多设备共享 SDA/SCL，必须开漏 + 外部上拉

// 按键用内部上拉
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;     // PB1, PA6, PA3
// 按键另一端接地，按下变低，不按被电阻拉到高

// LED 用推挽
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;  // PA1, PA2
// 直接驱动 LED，需要电流能力，推挽最合适
```

## 三、STM32 时钟树 — 心跳从哪来

### 3.1 时钟就是心跳

CPU 做任何操作都需要时钟节拍：取指令、存数据、外设通信。时钟越快 → 功耗越大、速度越快。

### 3.2 五大时钟源

```
                  ┌──────────────────────┐
   HSE (外部高速) │ 8MHz 晶振  精度高     │
                  ├──────────────────────┤
   HSI (内部高速) │ 8MHz RC振荡 精度一般  │
                  ├──────────────────────┤
   LSE (外部低速) │ 32.768KHz 晶振        │ ← RTC 用它
                  ├──────────────────────┤
   LSI (内部低速) │ ~40KHz RC振荡         │
                  ├──────────────────────┤
   PLL (锁相环)   │ HSI/ HSE × 倍频       │ ← 产生 72MHz
                  └──────────────────────┘
```

### 3.3 你项目的时钟路径

```
外部 8MHz 晶振 (HSE)
    ↓
PLL 9 倍频 = 72MHz
    ↓
SYSCLK = 72MHz
    ├── AHB 总线 = 72MHz  → CPU、DMA、SRAM
    ├── APB1 = 36MHz      → TIM2、I2C、USART、RTC 电源
    └── APB2 = 72MHz      → GPIO、TIM1、ADC、SPI
```

**为什么 APB1 是 36MHz？** APB1 最大只能 36MHz（硬件限制），时钟树自动除以 2。

### 3.4 TIM2 的时钟路径

```
72MHz (SYSCLK)
  → 72MHz (AHB)
    → 36MHz (APB1 Timer Clock 因为有倍频，实际 72MHz)
      → ÷ 720 (PSC)  = 100KHz (每个 tick = 10μs)
        → ÷ 100 (ARR) = 1000Hz (每 1ms 中断)
```

> 这里有个坑：APB1 分频器 ≠ 1 时，Timer 时钟 = APB1 × 2。所以 TIM2 实际跑在 72MHz 而非 36MHz。

### 3.5 为什么需要开各种时钟

```c
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);  // 用 PB 口必须先开时钟
RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);   // 用定时器必须先开时钟
```

**省电设计：** 默认所有外设时钟关闭。用哪个开哪个。如果忘了开——外设不工作，代码跑飞。

## 四、中断和 NVIC

### 4.1 什么是中断

```
正常执行：main → 读按键 → 画屏幕 → 读按键 → 画屏幕 → ...
                         ↑
中断发生：main → 读按键 → ╋ 啪！TIM2 中断来了
                         │ → CPU 暂停 main
                         │ → 跳去执行 TIM2_IRQHandler()
                         │ → 处理完返回
                         └ → 继续画屏幕
```

**中断让 CPU 可以"同时"做多件事。** 主循环画屏，定时器在后台精确计时。

### 4.2 NVIC 优先级

```c
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
// 分组 2：4 位优先级 → 2 位抢占 + 2 位响应
// 抢占优先级：0~3（高的可以打断低的）
// 响应优先级：0~3（同级抢占时，响应高的先处理）
```

| 抢占优先级 | 响应优先级 | 效果 |
|:---:|:---:|:---|
| 0 | 0 | 最高优先级，可以打断任何人 |
| 2 | 1 | **你 TIM2 的配置** |
| 3 | 3 | 最低优先级 |

**同级抢占优先级不能互相打断，高抢占优先级可以打断低抢占优先级的 ISR。**

### 4.3 你项目里只有一个中断

```c
NVIC_InitStructure.NVIC_IRQChannel = TIM2_IRQn;          // TIM2
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2; // 抢占 2
NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;        // 响应 1
```

只有一个中断时优先级无所谓。后面加更多中断（比如 MPU6050 的 EXTI）时才需要考虑谁优先。

## 五、I2C 总线 — OLED 怎么通信的

### 5.1 为什么要总线

没有 I2C：OLED 128×64 需要 1000+ 根线。  
有 I2C：**2 根线**（SCL + SDA），多个设备可以共享。

### 5.2 两根线各干什么

```
SCL (时钟线)：CPU 产生时钟节拍，控制通信节奏
SDA (数据线)：在每个时钟节拍传 1 bit 数据
```

### 5.3 通信流程

```
起始 → 发从机地址 → 发命令/数据 → ... → 停止

具体：
┌─ Start：SCL=高时，SDA 从高拉低
├─ 地址：0x78（OLED 的 I2C 地址）
├─ 控制字节：0x00=命令, 0x40=数据
├─ 数据字节：N 个，每个 8 位 + ACK
└─ Stop：SCL=高时，SDA 从低拉高
```

```
波形示意：
SCL: _─┐   ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐   ┌─┐ ┌─┐
      └─┘ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │...│ │ │ │
SDA: ───┐│ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │   │ │ │ │
        └┘ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │...│ │ │ │
Start  ─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘   └─┘ └─┘ ─→ Stop
         D7  D6  D5  D4  D3  D2  D1  D0  ACK
```

### 5.4 为什么用开漏

```
正常推挽：设备 A 输出高，设备 B 输出低 → 短路！烧芯片！
开漏 + 上拉电阻：
  - 任何设备都可以把总线拉低（开 N-MOS）
  - 没有设备能主动输出高，全靠电阻上拉
  - 不会短路，允许多设备共享
```

这就是你 `OLED.c` 里 `GPIO_Mode_Out_OD` 的原因。

### 5.5 你的 OLED 代码对应

```c
OLED_I2C_Start()     → 产生起始条件
OLED_I2C_SendByte()  → 发 8 位数据 + 等 ACK
OLED_WriteCommand()  → Start + 0x78 + 0x00 + 命令 + Stop
OLED_WriteData()     → Start + 0x78 + 0x40 + N字节数据 + Stop
OLED_Update()        → 循环 8 页，每页 WriteData 128 字节
```

## 六、外设寄存器 — 软件控制硬件的桥梁

### 6.1 寄存器就是芯片里的"开关"

```c
GPIOB->ODR = 0x0100;  // PB8 输出高
//    ↑        ↑
//  寄存器    写入值
//  (硬件地址) (控制位)
```

你写的 `GPIO_WriteBit(GPIOB, GPIO_Pin_8, 1)` 底层就是在操作寄存器。

### 6.2 外设怎么工作的

```
软件                    硬件
  │                       │
  ├─ 写配置寄存器 ──→   配置生效
  ├─ 写数据寄存器 ──→   硬件动作（如 I2C 发数据）
  ├─ 读状态寄存器 ←──   硬件反馈（如发送完成）
  └─ 清标志位    ──→   准备下一次操作
```

**库函数帮我们封装了寄存器操作：**

```c
// 不用库（裸寄存器）：
TIM2->PSC = 720 - 1;
TIM2->ARR = 100 - 1;

// 用标准外设库（你的代码）：
TIM_TimeBaseInitStructure.TIM_Prescaler = 720 - 1;
TIM_TimeBaseInitStructure.TIM_Period = 100 - 1;
TIM_TimeBaseInit(TIM2, &TIM_TimeBaseInitStructure);
```

库函数 = 给寄存器套了层可读的壳，本质一样。

### 6.3 核心原则

> **做任何操作前，先配置 → 再启动 → 等完成 → 清标志**

```c
// 定时器例子：
RCC_APB1PeriphClockCmd(TIM2, ENABLE);   // 1. 开时钟（不然寄存器都写不进去）
TIM_TimeBaseInit(TIM2, &cfg);           // 2. 配置参数
TIM_ITConfig(TIM2, TIM_IT_Update, ENABLE); // 3. 使能中断
TIM_Cmd(TIM2, ENABLE);                  // 4. 启动

// 记得清标志位，否则一启动就误进一次中断：
TIM_ClearFlag(TIM2, TIM_FLAG_Update);
```

## 七、常用术语速查

| 术语 | 全称 | 含义 |
|:---|:---|:---|
| GPIO | General Purpose I/O | 通用输入输出引脚 |
| I2C | Inter-Integrated Circuit | 两线串行总线 |
| RTC | Real Time Clock | 实时时钟 |
| TIM | Timer | 定时器/计数器 |
| NVIC | Nested Vectored Interrupt Controller | 嵌套向量中断控制器 |
| PSC | Prescaler | 预分频器（分频用的） |
| ARR | Auto-Reload Register | 自动重装载值（周期） |
| PLL | Phase-Locked Loop | 锁相环（倍频用） |
| SRAM | Static RAM | 运行内存（掉电丢失） |
| Flash | Flash Memory | 程序存储器（掉电保留） |
| ISR | Interrupt Service Routine | 中断服务函数 |
| CMSIS | Cortex Microcontroller Software Interface Standard | ARM 微控制器软件接口标准 |
