## 二、游戏主循环

### 2.1 双线程协作

```
TIM2 中断（每 1ms）              主循环
─────────────────              ─────────
Dino_Tick()                    DinoGame_Animation()
  ├── 分数 +1（每100ms）            ├── OLED_Clear()
  ├── 地面滚动（每20ms）           ├── Show_Score()
  ├── 障碍物移动（每20ms）         ├── Show_Ground()
  ├── 云朵移动（每50ms）           ├── Show_Barrier()
  └── 跳跃计时                     ├── Show_Cloud()
                                   ├── Show_Dino()
                                   ├── OLED_Update()
                                   └── isColliding() 碰撞检测
```

**ISR 管数值（位置/分数），主循环管渲染。** 和秒表一模一样的模式。

### 2.2 游戏结束

```c
if (isColliding(&dino, &barrier))
{
    OLED_ShowString("Game Over");
    Delay_s(1);       // 停留 1 秒看结果
    return 0;          // 退出游戏，回到菜单
}
```

## 三、地面卷轴滚动

### 3.1 原理

Ground 是 256 字节的地面纹理，但屏幕只有 128 宽。滚动就是改变起始位置：

```c
uint16_t Ground_Pos;  // 当前滚动偏移

// 情况1：Ground_Pos < 128，一镜到底
Ground[Ground_Pos ... Ground_Pos+127] → 屏幕

// 情况2：Ground_Pos ≥ 128，需要拼接
Ground[Ground_Pos ... 255]  → 屏幕前段
Ground[0 ... Ground_Pos-128] → 屏幕后段
```

### 3.2 为什么直接操作 DisplayBuf

```c
OLED_DisplayBuf[7][i] = Ground[i + Ground_Pos];
```

地面写在第 7 页（Y=56~63），直接写显存缓冲区，不经过 `OLED_ShowImage`。速度更快，且地面变化频率高（每 20ms 移动 1px）。

## 四、跳跃物理 — sin 函数抛物线

### 4.1 为什么用 sin

`sin(0 ~ π)` 的形状是 0→1→0，天然形成抛物线：

```
Jump_Pos = 28 × sin(π × jump_t / 1000)

jump_t: 0   250   500   750   1000
sin值:  0   0.7   1.0   0.7   0
高度:   0   20    28    20    0     (28×sin值)

       ┌─┐
      ┌┘ └┐         ← 抛物线轨迹
     ┌┘   └┐
────┘       └──────────────────  地面
```

### 4.2 跳跃状态机

```c
// 跑步状态
if (dino_jump_flag == 0)
{
    // 两帧交替 = 跑步动画
    if (Cloud_Pos % 2 == 0)  显示 Dino[0]（左脚）
    else                      显示 Dino[1]（右脚）
}

// 跳跃状态
if (dino_jump_flag == 1)
{
    显示 Dino[2]（跳跃姿势）
    Jump_Pos = 28 * sin(π * jump_t / 1000);  // 计算高度
    jump_t++;
    if (jump_t >= 1000)                      // 跳跃结束
    {
        jump_t = 0;
        dino_jump_flag = 0;                   // 回到跑步
    }
}
```

## 五、碰撞检测 — 包围盒（AABB）

### 5.1 原理

每个物体有一个矩形包围盒：

```c
struct Object_Position {
    uint8_t minX, minY;  // 左上角
    uint8_t maxX, maxY;  // 右下角
};
```

### 5.2 碰撞判断

两个矩形相交 = 四个条件同时满足：

```c
int isColliding(struct Object_Position *a, struct Object_Position *b)
{
    if ((a->maxX > b->minX) &&   // a 的右边 > b 的左边
        (a->minX < b->maxX) &&   // a 的左边 < b 的右边
        (a->maxY > b->minY) &&   // a 的下边 > b 的上边
        (a->minY < b->maxY))     // a 的上边 < b 的下边
    {
        return 1;  // 碰撞！
    }
    return 0;
}
```

```
      minX           maxX
        ┌──────────────┐
        │              │
  minY  │     Dino     │
        │              │
  maxY  └──────────────┘
              ┌────┐
              │障碍│    ← 如果两个矩形重叠 → 撞了
              └────┘
```

## 六、帧动画 — 多帧精灵

```c
// 跑步有两帧，按 Cloud_Pos 奇偶交替
if (Cloud_Pos % 2 == 0)
    Dino[0]  // 左脚在前
else
    Dino[1]  // 右脚在前

// 跳跃一帧
Dino[2]  // 跳起姿势
```

`Cloud_Pos` 本来是用来移动云朵的变量，顺带借来当帧计数器——每 50ms 切换一次，刚好是合理的跑步帧率。
