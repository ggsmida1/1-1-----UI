# 1-7 小恐龙游戏 — 学习笔记

## 学习目标

本节重点是学习在裸机项目中实现简单游戏循环：画面刷新在应用循环中进行，角色和场景状态由 1ms tick 推进。

对应代码：

- `APP/src/app_dino.c`
- `APP/src/app_tick.c`
- `RES/src/ui_resources.c`
- `HARDWARE/src/OLED.c`

## 单片机知识点

### 1. 游戏循环

游戏运行时不断执行：

```text
清屏 -> 绘制分数 -> 绘制地面 -> 绘制障碍物 -> 绘制云 -> 绘制角色 -> 刷屏 -> 碰撞检测
```

这就是一个最小游戏主循环。

### 2. tick 和绘制分工

项目里分成两部分：

- `App_Dino_Tick()`：推进分数、地面位置、障碍物位置、云位置、跳跃时间。
- `App_Dino_Run()`：执行游戏主循环和 OLED 绘制。

这样中断不直接画屏幕，页面循环也不负责精确计时。

### 3. 直接写 OLED 显存

地面滚动直接操作 `OLED_DisplayBuf`：

```c
OLED_DisplayBuf[7][i] = Ground[i + Ground_Pos];
```

原因是地面是一整行滚动图案，直接写显存比逐个调用绘图函数更直观。

### 4. AABB 碰撞检测

项目使用矩形包围盒判断碰撞：

```text
a.maxX > b.minX
a.minX < b.maxX
a.maxY > b.minY
a.minY < b.maxY
```

四个条件都成立，说明两个矩形重叠。

## 代码解析

### `App_Dino_Run()`

应用入口先初始化位置，再启动游戏动画：

```c
DinoGame_Pos_Init();
return DinoGame_Animation();
```

菜单层不需要知道游戏内部初始化细节。

### `Show_Dino()`

角色有跑步和跳跃两种状态：

- `dino_jump_flag == 0`：跑步帧交替。
- `dino_jump_flag == 1`：根据 `jump_t` 计算跳跃高度。

跳跃高度使用 `sin()`：

```c
Jump_Pos = 28 * sin(pi * jump_t / 1000);
```

### `isColliding()`

碰撞后显示 `Game Over`，延时 1 秒，然后返回菜单。

## 注意点

- `Score`、`Ground_Pos` 等游戏状态目前是全局变量，适合当前规模，但不是可复用游戏引擎。
- `App_Dino_Tick()` 在 1ms tick 中执行，只推进状态，不画 OLED。
- `Delay_s(1)` 会阻塞游戏结束画面，这是当前交互可接受的简单做法。
- 障碍物随机使用 `rand()`，当前没有设置随机种子。
